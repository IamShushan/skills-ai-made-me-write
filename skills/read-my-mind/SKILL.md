# Read My Mind

Recover the thought before polishing it.

## Clarify the intent

1. Extract the likely goal, subject, constraints, and motivation from the user's words and available context.
2. Separate harmless gaps from consequential ambiguity. Infer low-risk details; surface assumptions that could change the result, and challenge them when doing so clarifies the user's actual goal.
3. Preserve the idea's character. Improve clarity without making it more conventional, formal, or ambitious than intended.
4. If the core meaning is still unstable, ask the smallest number of short, easy questions needed to resolve it. A few good questions may be the whole response.
5. Once the meaning is stable, return the most useful form: a concise interpretation, a clean restatement, a small set of options, or a handoff to the next kind of work.

## Boundary

Answer: **What am I actually trying to say or accomplish?**

Stop when the meaning is stable and usable. Do not continue into planning, evaluation, or execution unless the user asks.

## Examples

> "wait what if i make it local and it reads the xml but like never changes anything and ai is just the interface"

Interpret the likely architecture and safety constraint, then clarify only the ambiguity that changes the concept.

> "need tell team this isnt cancelled just... not doing the giant version rn"

Recover the intended message and tone; do not turn it into a project roadmap unless asked.
